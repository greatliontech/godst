# DST audit hardening and optimization sequence

**Lands:** before new DST features.

## Audit scope

Full DST changeset audit: `git diff go1.26.4..HEAD`.

Authoritative contract: `docs/dst/design.md`.

Sequence rule: items are ordered **bottom-up** by dependency layer, not by severity. Fix lower substrate issues before relying on higher-level API, package-seam, and feature work.

## Bottom-up sequence

| Seq | Severity | Finding | Hardening / optimization action |
|-----|----------|---------|----------------------------------|
| BU-01 | H | Nested or overlapping `simulation.Run` can corrupt global DST state. `run` mutates `GOMAXPROCS`, async preempt, strategy, sim identity, memory limit, and `dstSeed` before `synctest.Run` rejects nested bubbles (`src/testing/simulation/simulation.go:324`, `src/testing/simulation/simulation.go:328`, `src/runtime/synctest.go:187`). An inner `Run` inside an outer run can panic, recover, run `dstDeactivate`, and clear the outer run's state while the outer bubble continues. | Reject `Run` when already inside a synctest bubble before any state mutation, and add a process-global non-overlap guard/serialization for concurrent top-level runs. Add a regression that recovers from an inner `Run` panic and then proves the outer run still has DST scheduling/RNG/identity active. |
| BU-02 | H | SUT code can disable the scheduler seam by changing `GOMAXPROCS` inside `Run`. `Run` pins once (`src/testing/simulation/simulation.go:328`), while `findRunnable` uses `dstFindRunnable` only when `gomaxprocs == 1` (`src/runtime/proc.go:3499`). A SUT calling `runtime.GOMAXPROCS(2)` or `SetDefaultGOMAXPROCS` escapes the seeded single-P schedule. | While `dstActive`, make public `GOMAXPROCS` changes no-op/panic or route them through a runtime pin that SUT code cannot override; restore only after `dstDeactivate`. Test same-seed replay after an attempted in-run `GOMAXPROCS(2)`. |
| BU-03 | H | Run-end `sync.Pool` reap happens after `dstDeactivate`, so pooled finalizer/cleanup objects can be discovered by ordinary async workers without a bubble. `dstStopGCDrain` stops when no callback is pending (`src/runtime/synctest.go:481`), then the defer deactivates DST and runs two ordinary GCs (`src/testing/simulation/simulation.go:337`, `src/testing/simulation/simulation.go:347`). A final `Pool.Put` can require two pool-generation GCs before the object becomes unreachable, so a channel-touching callback can later run on `fing`/cleanup workers with `g.bubble == nil`. | Fold the two-generation `sync.Pool` eviction into the in-bubble run-end drain before `dstDeactivate`, and count pool-generation advancement as fixpoint progress. Add pooled-finalizer and pooled-cleanup tests that touch bubble channels. |
| BU-04 | M | Finalizer/cleanup panics on the DST drain are not reported by `Explore`. The public API docs promise child-goroutine panics are recorded (`src/testing/simulation/explore.go:59`), but `dstExploreRecordUncaughtPanic` excludes `gp.bubble.gcDrain` (`src/runtime/dst_explore.go:579`). A user callback panic can crash the process instead of returning `Failure.Panic`. | Treat drain callback panics as SUT panics for scheduled exploration, then terminate the scheduled run without leaving a dead drain. Add finalizer and cleanup panic tests for `Explore`/`Replay`. |
| BU-05 | H | Scheduled replay identity can collide across repeated `Explore` runs. `dstScheduleReset` resets `dstSeqCtr` but does not clear the existing synctest root goroutine's `dstSeq` or pending access fields (`src/runtime/dst_explore.go:677`, `src/runtime/synctest.go:202`); only newly allocated/reused goroutines are cleared in `newproc1` (`src/runtime/proc.go:5425`). Reusing a stale root seq can make a later SUT goroutine receive the same seq, making schedule prefixes and HB edges ambiguous. | Clear the current/root goroutine's scheduled fields at bubble entry and/or exit. Add a trace invariant test that every enabled set has unique `dstSeq` values and that root/drain seqs cannot collide with SUT goroutines across repeated `Explore` calls. |
| BU-06 | M | RWMutex DST HB modeling can over-order failed public operations. `RWMutex.TryLock` first succeeds on the embedded writer mutex, then can fail the public write lock at `readerCount.CompareAndSwap` (`src/sync/rwmutex.go:178`). The embedded `Mutex.TryLock` emits DST acquire HB (`src/internal/sync/mutex.go:86`, `src/internal/sync/mutex.go:109`) and the compensating `rw.w.Unlock` emits release HB (`src/internal/sync/mutex.go:215`), even though a failed public `TryLock` must not synchronize per the Go memory model. | Suppress internal writer-mutex HB while executing RWMutex admission internals, and emit explicit DST HB only for public successful `Lock`/`TryLock`, `Unlock`, `RLock`/`TryRLock`, and `RUnlock` edges matching the Go memory model. Add a failed-`TryLock` DPOR regression. |
| BU-07 | M | DPOR's offline HB relation misses several synchronization edges the race detector models. RWMutex records decision conflicts but not explicit public release/acquire events for `readerSem`/`writerSem` (`src/sync/rwmutex.go:49`, `src/sync/rwmutex.go:72`, `src/sync/rwmutex.go:126`, `src/sync/rwmutex.go:216`). Channel HB is recorded for buffered slots but not all unbuffered rendezvous or close-to-closed-receive paths (`src/runtime/chan.go:444`, `src/runtime/chan.go:605`, `src/runtime/chan.go:748`). This can over-explore and hit budgets for synchronized SUTs. | Add DST sync events mirroring the race detector's RWMutex annotations and channel close/unbuffered HB. Add tests like the existing buffered-channel/mutex HB tests for `Unlock -> RLock`, `RUnlock -> Lock`, unbuffered send/receive, and close-to-receive. |
| BU-08 | M | The live shared-address filter does not consume sync HB. `dstAccessShouldYield` checks only the live per-g clocks (`src/runtime/dst_explore.go:418`), ready edges merge live clocks (`src/runtime/dst_explore.go:515`), but sync release/acquire events are appended only for offline analysis (`src/runtime/dst_explore.go:558`). Mutex/channel-HB-ordered accesses can still become yield points, contrary to the filtering design, inflating traces and `MaxSteps` pressure. | Maintain live object clocks for `dstRecordSyncRelease`/`dstRecordSyncAcquire`, or add another live-HB mechanism that lets the access filter see synchronization. Add trace-length/yield-count tests for repeated mutex/RWMutex/channel-protected accesses. |
| BU-09 | M | Resolved: Level-2 build-isolation contract was stronger than the implementation. `runtime.g` has DST fields unconditionally (`src/runtime/runtime2.go:510`), `dst_explore.go` is compiled without `dst`/`race` build tags (`src/runtime/dst_explore.go:1`), and hook branches are present in normal source paths behind constants (`src/internal/sync/mutex.go:66`, `src/runtime/chan.go:196`, `src/runtime/select.go:265`). If `DST-L2-4` really meant byte-identical non-DST and dst-without-race builds, this changed layout/source artifacts even when behavior was gated. | Amended `DST-L2-4` to the selected build-mode inertness contract and added `TestDSTAccessYieldBuildModeInert` to prove scalar and range access-yield hooks are emitted only under `-tags dst -race`. |
| BU-10 | M | Resolved: `RunWith`/replay API and validation did not match the design. `docs/dst/design.md` described `Options{Strategy: DPOR, Schedule: s}` replay, but public `Options` exposes only `Random`/`PCT` fields (`src/testing/simulation/simulation.go:155`, `src/testing/simulation/simulation.go:182`) and scheduled replay is through `Replay`/internal `run`. Unknown `Strategy` values silently ran Random because only `PCT` was special-cased (`src/testing/simulation/simulation.go:289`). `Depth`/`Steps` also converted to `int32` without bounds checks (`src/testing/simulation/simulation.go:296`). | Amended the design to the landed `Explore`/`Replay` API, made `RunWith` reject unknown strategies, and made positive PCT `Depth`/`Steps` panic before activation if they exceed the runtime scheduler's `int32` field. |
| BU-11 | H | Resolved: typed and packet network APIs bypassed DST and could open real host sockets. The DST fast path was only in string `DialContext` and `Listen` (`src/net/dial.go:529`, `src/net/dial.go:878`). Typed APIs and packet listeners fell through to OS dial/listen paths (`src/net/dial.go:606`, `src/net/dial.go:620`, `src/net/dial.go:634`, `src/net/dial.go:648`, `src/net/dial.go:917`). | Added DST guards to typed TCP/UDP/IP/Unix dial/listen paths and `ListenPacket`; these public entry points now return a deterministic unsupported-network-API error under `simulation.Run` instead of reaching the host OS. Added `TestDSTNetTypedAndPacketAPIsDoNotTouchHost`. |
| BU-12 | M | Resolved: `Dialer` and `ListenConfig` options were silently ignored on the DST fast path. `DialContext` dropped the `Dialer` before calling `dstDial` (`src/net/dial.go:529`, `src/net/dst.go:291`); `Listen` dropped `ListenConfig` before `dstListen` (`src/net/dial.go:878`, `src/net/dst.go:244`). `LocalAddr`, `Control`, `ControlContext`, MPTCP, and keepalive semantics could silently differ from production. | Passed `Dialer`/`ListenConfig` into the DST shim, honored compatible `Dialer.LocalAddr`, accepted explicit MPTCP disable as ordinary TCP, and rejected explicit raw-fd/MPTCP-enable/keepalive options with deterministic unsupported-option errors. Added option-behavior tests. |
| BU-13 | M | Resolved: DST net errors lost standard error identity. Refused connections and duplicate listen used fresh `errors.New` values (`src/net/dst.go:276`, `src/net/dst.go:323`, `src/net/dst.go:344`), so `errors.Is(err, syscall.ECONNREFUSED)` / `EADDRINUSE` could fail under DST while succeeding in production-shaped code. | Preserved production-shaped error identity by using `syscall.ECONNREFUSED` for refused connects and `syscall.EADDRINUSE` for duplicate listens under the existing `*OpError` wrapper. Added `TestDSTNetErrorIdentity`. |
| BU-14 | M | Direct DNS resolver APIs still use the host resolver inside `Run`. The design rejects DNS through `Dial`/`Listen`, but public `net.Lookup*` / `Resolver` methods are not gated and can do host DNS I/O. | Gate public lookup/resolver APIs under DST with the same deterministic unsupported error, or explicitly narrow the contract and track DNS virtualization as a separate issue. Add a test that `net.LookupHost("example.com")` does not reach the host resolver inside `Run`. |
| BU-15 | M | Process identity is only partially virtualized despite broad contract language. `os.Getgroups` still returns host groups (`src/os/proc.go:80`), and `os/user.Lookup`, `LookupId`, `LookupGroup`, `LookupGroupId`, and `User.GroupIds` fall through to host user/group databases except for the current simulated user fast path (`src/os/user/lookup.go:46`, `src/os/user/lookup.go:64`, `src/os/user/lookup.go:75`). | Simulate a fixed group list and minimal user/group database, or narrow the spec/package docs to current-user-only and add tests for the chosen boundary. |
| BU-16 | M | The crypto/rand outside-run test can pass even if outside-run bytes are still deterministic. The test program only checks that two outside reads differ within one process (`src/runtime/testdata/testprog/dst.go:485`), and the parent test compares only the printed booleans across processes (`src/runtime/dst_test.go:875`). A bad mutation that leaves `dstActive` true after `Run` but advances the deterministic stream can still print `realdiffers=true`. | Assert `runtime.dstActive` is false after `Run` in the test program and/or print/compare outside-run bytes across separate processes so deterministic outside-run output is caught. |
| BU-17 | L | `httptrace`/nettrace connect callbacks are skipped by the DST dial fast path. `DialContext` returns from `dstDial` before trace extraction (`src/net/dial.go:529`), so `ConnectStart`/`ConnectDone` are not fired around simulated connects. | Move the DST fast path after trace extraction or explicitly fire `ConnectStart`/`ConnectDone` around `dstDial`. Add an `httptrace` regression. |
| BU-18 | L | Authoritative docs/spec drift on GC drain timing. `docs/dst/design.md` says the built drain still runs at quiescence (`docs/dst/design.md:1629`) and later says Chunk B's drain runs per-GC (`docs/dst/design.md:1684`), while implementation drains at quiescence (`src/runtime/synctest.go:439`). | Amend the design to separate per-cycle discovery from quiescence callback execution, or change implementation/tests if per-GC execution is the intended contract. |
| BU-19 | L | Package docs still describe GC trigger byte accounting noise after the implementation moved the trigger to per-object `dstHeapAlloc`. The package overview says per-cycle discovery is deterministic (`src/testing/simulation/simulation.go:42`), but `Run` docs still say the exact heap byte carries process-layout noise (`src/testing/simulation/simulation.go:254`), while design describes the per-object trigger (`docs/dst/design.md:1764`). | Update public docs to distinguish unsupported byte-level `MemStats` noise from the now-contractual per-object trigger and per-cycle discovery. |
| BU-20 | L | Roadmap status is stale for Level 2. The roadmap still lists Level 2 / DPOR as pending (`docs/dst/design.md:419`) while public `Explore`, `ExploreWith`, and `Replay` exist (`src/testing/simulation/explore.go:147`, `src/testing/simulation/explore.go:160`, `src/testing/simulation/explore.go:174`) and the detailed section says validated/implemented. | Move Level 2 to Landed and align package overview docs, or hide/remove the public API until it is intended to be supported. |
| BU-21 | Opt | Access filtering scans all recorded access entries on every auto-instrumented access (`src/runtime/dst_explore.go:434`), an O(A^2) path for heap-heavy SUTs even when most accesses are private or non-overlapping. | Replace the full scan with interval/page buckets or another range index for overlap candidates. Keep conservative overflow behavior. |
| BU-22 | Opt | Forced-access replay checks scan every forced triple on every access (`src/runtime/dst_explore.go:409`), O(A*F) as promotion grows. | Sort installed forces and binary-search, or shard by `seq` / `(seq,count)` for constant or logarithmic lookup. |

## Close-out criteria

- Each sequence item is either fixed with regression coverage, deliberately folded into another tracked issue, or the spec is amended to the chosen contract.
- No package seam that is marked unsupported falls through to host OS/network/user/database I/O inside `simulation.Run`.
- `docs/dst/design.md` and `testing/simulation` package docs agree on landed API and GC timing/discovery contracts.
- Optimization items are handled after correctness items that affect the same code path, unless the optimization is the simplest way to make an invariant enforceable.
